NAACL 2027 System Demonstrations

Environment Drift in Self-Improving LLM Agents: Measuring Reference Staleness and False Promotions

An interactive replay of five measured runs on GSM8K: an agent rewrites its own instruction, the answer extractor changes underneath it, and a stale reference lets weaker instructions through. Step 8 shows how the same system maps onto financial QA and code generation, without results for those tasks.

    Seed 5 opens first because every false promotion it makes after a change traces to the stale reference. All five seeds are selectable, and the dashboard pools them.

    What this is

    The page replays runs that were computed in advance, so every accuracy, win count and false-accept count was measured and nothing is generated here. The agent is Qwen2.5-1.5B-Instruct solving GSM8K word problems. It rewrites its own instruction each round, and a candidate instruction is promoted if it wins more questions than it loses against a stored reference.

    Midway through each run the environment changes: decoding first, then decoding and the answer extractor together. The lenient extractor accepts everything the strict one does and some more, so it can only add credit. A reference scored before the change and a candidate scored after it are no longer measured with the same ruler.

    What it does not show

    One model, one task and two kinds of change, over five seeds. Promotion and the check that labels a promotion false use the same 200 questions, and the check measures both instructions in the environment in force. Call counts are logical counts from a dry run, not measured inference cost. The section on other applications is an illustration and reports no results. Financial QA and code generation were not evaluated.
